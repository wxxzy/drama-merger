# 11 · 踩坑集锦：那些「不查不知道」的坑

> 这份文档记录开发过程中真实遇到的坑与解法。读懂它们，能帮你理解代码里很多
> 「看起来多余」的写法——它们几乎都是被 bug 逼出来的。

## 坑 1：23 毫秒时间戳偏移

**现象**：用 concat demuxer + `-c copy` 拼接后，输出起始时间变成
`video=0.100s / audio=0.076s`，时长多出 23ms。

**排查**：

```
纯 concat + -c copy        → 视频起始 0.023s，时长 18.023s
加 -copyts                 → 起始 0.000s，时长精确 18.000s，帧数 432 = 18×24
```

**解法**：拼接阶段用 `-copyts`，并去掉 `-fflags +genpts` 和 `-avoid_negative_ts`。
单看 23ms 不起眼，但**逐集累积会造成长剧集音画漂移**，必须修掉。

## 坑 2：无音轨片段拼接失败

**现象**：策略 C 用 `anull` 给无音轨片段补音轨，报错 `matches no streams`。

**原因**：`anull` 是音频滤镜，不能接视频流。

**解法**：追加一路独立的 lavfi 静音输入：`anullsrc=r=...:cl=...:d=...`，
且**必须指定时长**——不指定的话无限长音源会让 concat 永不完结。

## 坑 3：ffmpeg 子进程死锁假死

**现象**：合并 20+ 集时程序无输出、假死。

**原因**：原本串行读 stdout 再读 stderr。ffmpeg 拼接多集时往 stderr 输出大量
`Non-monotonic DTS` 警告，填满 stderr 管道缓冲区（Windows 约 64KB），
ffmpeg 阻塞在写 stderr 上，不再写 stdout 进度；主线程却在等 stdout → 互等死锁。

**解法**：用**两个独立线程**分别泵 stdout 和 stderr（见 [05](./05-合并策略引擎-merger.md)）。

## 坑 4：NVENC 的音画起点差

**现象**：归一化阶段混用 `-avoid_negative_ts make_zero`，加上 NVENC 约 3 帧编码延迟，
固化成 24ms 的音画起点差。

**解法**：归一化命令里刻意**不加** `-avoid_negative_ts`，保证各片段起始干净归零。
防负时间戳的职责交给最终拼接阶段。

## 坑 5：NVENC「编译时包含」≠「运行时可用」

**现象**：ffmpeg 8.1.2 有 `h264_nvenc`，但编码报驱动 API 版本不符。

**解法**：不硬编码，启动时真跑一次编码测试（`_verify_nvenc`），据此择优（见 [03](./03-环境探测.md)）。

## 坑 6：压缩 + 淡变二次压缩

**现象**：指定压缩档位又有淡变时，归一化压一次、淡变再压一次，画质二次损失。

**解法**：归一化阶段检测有淡变就**不压缩**（`use_compress = compress and not fade`），
把压缩留到最终淡变编码一次完成。

## 坑 7：策略 E 永远选不中

**现象**：加了压缩功能后，参数一致的素材本应走策略 E，却总走 B。

**原因**：`needs_reencode` 把 compress 算进去了，而 `choose_strategy` 里
选 E 的条件用了错误的属性判断。

**解法**：拆出 `needs_filter_processing`（只含裁剪/淡变）——压缩不妨碍 concat demuxer 直连。
选 E 看的是 `is_uniform and not needs_filter_processing`。

## 坑 8：模板放错位置拖累 CLI

**现象**：打包版 CLI 的 publish 子命令依赖 tkinter。

**原因**：剧目文案模板原本写在 `gui.py`，CLI 调用时要 import gui。

**解法**：把模板数据下沉到 `publish.py`（库模块），GUI/CLI 都从库取（见 [08](./08-发布准备流水线.md)）。

## 坑 9：打包版 PIL 被误排除

**现象**：打包版发布素材时缩略图生成失败。

**原因**：`build.spec` 的 excludes 里排除了 PIL。

**解法**：从 excludes 移除 PIL。

## 坑 10：windowed GUI 的 stdout 为 None

**现象**：GUI 版 exe 双击闪退。

**原因**：`console=False` 打包后 `sys.stdout` 是 `None`，底层 print 崩溃。

**解法**：entry 里用 `_NullWriter` 兜底 stdout/stderr（见 [09](./09-命令行与图形界面.md)）。

## 坑 11：entry 里 chdir 导致输出「消失」

**现象**：GUI 里设相对输出路径，文件跑到 exe 目录里。

**解法**：移除两个 entry 里的 `os.chdir(exe目录)`，保持调用者工作目录。

## 坑 12：缩略图上封面自带红字重复

**现象**：生成的缩略图上，右侧封面自带剧名红字 + 左侧新加标题，重复难看。

**排查**：用红色像素扫描定位封面底部红字从 y=930（约 77.5%）开始。

**解法**：模板里设 `bottom_cut=0.235` 裁掉底部区域，缩略图 md5 与手工版字节级一致。

## 坑 13：GUI 按钮被挤出窗口

**现象**：用户截图里看不到「开始合并」按钮。

**解法**：把主按钮移到「4. 输出选项」区底部、加大窗口到 900×760，
并最终改用标签页分区（见 [09](./09-命令行与图形界面.md)）。

## 坑 14：BAT 换行符 / 编码

**现象**：`.bat` 报 `'xx' 不是内部或外部命令`。

**解法**：CRLF 换行 + GBK 编码（见 [10](./10-打包成免安装程序.md)）。

## 小结

这 14 个坑覆盖：时间戳、滤镜、并发死锁、硬件编码、策略选择、打包、UI 布局、BAT 编码。
它们的共同点是——**都靠实测发现、都在代码里留下了防御性处理**。
读懂这一篇，你就明白代码里很多「奇怪」写法的由来了。
