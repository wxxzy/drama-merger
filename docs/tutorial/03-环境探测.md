# 03 · 环境探测：ffmpeg 发现与 NVENC 实测

> 对应源码：`drama_merger/ffmpeg_env.py`
> 学习目标：理解工具如何「找到 ffmpeg」并「判断它到底能不能用硬件编码」。

## 为什么需要专门的探测模块

你可能觉得：ffmpeg 不就是个可执行文件吗，直接调用就行了？

但这个工具遇到的真实情况是——同一台机器上装了**两个 ffmpeg，NVENC 支持情况完全相反**：

| ffmpeg | 版本 | NVENC 状态 |
|---|---|---|
| `imageio_ffmpeg` 自带 | 7.1 | 可用 ✅ |
| WinGet (Gyan full) | 8.1.2 | 不可用 ❌ |

新版的 8.1.2 反而报错：

```
Driver does not support the required nvenc API version.
Required: 13.1  Found: 12.2
The minimum required Nvidia driver for nvenc is 610.00 or newer
```

因为显卡驱动 560.94 < 610.00。而旧版 ffmpeg 7.1 用的是较老的 NVENC API（12.x），反而能用。

**结论：绝不能硬编码「哪个 ffmpeg 好」或「能不能用硬件编码」，必须运行时实测。**

## 第一步：候选路径搜索

`_candidate_ffmpeg_paths()` 按优先级列出所有可能的 ffmpeg：

```python
# ffmpeg_env.py:62
def _candidate_ffmpeg_paths() -> list[Path]:
    cands = []
    # 1) 环境变量显式指定（最高优先级）
    for env_key in ("DRAMA_MERGER_FFMPEG", "FFMPEG_BINARY", "FFMPEG"):
        if os.environ.get(env_key):
            cands.append(Path(os.environ[env_key]))
    # 2) imageio_ffmpeg 自带（本机实测 NVENC 可用）
    ...
    # 3) PATH 中的 ffmpeg
    # 4) Python 脚本目录旁
    # 5) WinGet 安装的 Gyan build
    ...
    # 去重且保持顺序，过滤掉不存在的
```

注意环境变量优先级最高——这是打包版能「自带 ffmpeg」的关键：
`cli_entry.py` / `gui_entry.py` 启动时把捆绑的 ffmpeg 路径注入 `DRAMA_MERGER_FFMPEG`，
探测时它就会排第一。

## 第二步：逐个探测能力

`_probe_one()` 对每个候选ffmpeg，实际执行几条命令：

| 命令 | 得到什么 |
|---|---|
| `-version` | 版本号、build 信息 |
| `-encoders` | 编译时包含的编码器（如 `h264_nvenc`） |
| `-hwaccels` | 硬件加速方式 |
| `-filters` | 关键滤镜是否齐全 |

**关键点**：「编译时包含 `h264_nvenc`」≠「运行时能用」。所以还有第三步。

## 第三步：NVENC 实测

`_verify_nvenc()` 真的编码一小段测试视频：

```python
# ffmpeg_env.py:231
def _verify_nvenc(ffmpeg_path):
    tmp = Path(os.environ.get("TEMP", "/tmp")) / "drama_merger_nvenc_probe.mp4"
    cmd = [
        str(ffmpeg_path), "-hide_banner", "-loglevel", "error",
        "-f", "lavfi", "-i", "testsrc2=size=320x240:rate=30:duration=1",
        "-c:v", "h264_nvenc", "-preset", "p4", "-f", "mp4", "-y", str(tmp),
    ]
    code, out, err = _run(cmd, timeout=60)
    ok = code == 0 and tmp.is_file() and tmp.stat().st_size > 0
    ...
    return ok, error_message
```

用 `lavfi` 生成 1 秒测试源，真跑一次硬件编码，成功且产出非空文件才算「可用」。
这样无论驱动怎么升级、换哪个 ffmpeg，都能得到正确结论。

## 第四步：择优

`_pick_best()` 用打分选出最佳候选：

```python
# ffmpeg_env.py:291
def score(cap):
    return (
        1 if cap.nvenc_verified else 0,   # 硬件编码可用性权重最高
        1 if cap.ffprobe else 0,          # 有配套 ffprobe
        cap.version_tuple,                # 版本新旧兜底
    )
return max(self.candidates, key=score)
```

优先级：**NVENC 实测可用 > 有 ffprobe > 版本新**。

选出的结果通过 `FfmpegEnv` 暴露：

- `env.ffmpeg` —— 选中的 ffmpeg 路径
- `env.ffprobe` —— 配套探测工具
- `env.nvenc_available` —— 是否启用硬件编码

`get_ffmpeg_env()` 带缓存，避免每次调用都重新探测一遍。

## 与其他模块的关系

- `merger.py` 用 `env.ffmpeg` 构建所有命令；
- `merger.py` 用 `env.nvenc_available` 决定 `auto` 模式下走 NVENC 还是 x264；
- `probe.py` 用 `env.ffprobe`（没有则退化用 ffmpeg）探测媒体参数。

## 排错小贴士

运行 `python cli.py probe <目录> --refresh-env`（或 `--verbose`）会打印完整的
环境探测报告，列出每个候选的画像和「<== 已选用」标记。遇到编码异常时先看这份报告。

## 小结

- 多候选路径搜索，环境变量优先；
- 「编译时包含」不等于「运行时可用」，NVENC 靠实测；
- 择优打分：硬件编码 > ffprobe > 版本。
