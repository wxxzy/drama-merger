# 05 · 合并策略引擎（核心）

> 对应源码：`drama_merger/merger.py`
> 学习目标：这是整个工具的「大脑」。理解五种策略何时用、命令怎么构建、如何自动降级。

## 五种策略总览

`Strategy` 枚举定义了五档，按「代价从低到高」排列：

| 策略 | 名称 | 触发条件 | 画质 | 速度 |
|---|---|---|---|---|
| **A** | 无损拼接 | 参数一致且不裁剪/淡变/压缩 | **零损失** | 秒级（60x 实时） |
| **D** | 最小重编码 | 少数片段偏离（多数派 ≥ 50%） | 仅偏离片段损失 | 快一个数量级 |
| **E** | 合并即压缩 | 指定压缩档位且参数一致 | 一次损失 | 中（2x 实时） |
| **B** | 归一化拼接 | 参数有差异 / 有裁剪淡变 | 一次损失 | 快（4.8x 实时） |
| **C** | 滤镜重编码 | 强制指定 / 其他策略失败兜底 | 一次损失 | 最慢 |

**策略 A 是皇冠**：它不重新编码，只是把原始码流按顺序拼接（concat demuxer + `-c copy`），
所以「秒级完成 + 画质零损失」。短剧素材通常同源同参数，命中率很高。

## 两个易混淆的属性

`MergeOptions` 里有两个属性，决定了策略选择的正确性：

```python
# merger.py:87
@property
def needs_reencode(self) -> bool:
    """裁剪、淡变、压缩 —— 凡是不能纯 -c copy 的都算。"""
    return bool(self.trim_head or self.trim_tail or self.fade_in or self.fade_out
                or self.compress is not None)

@property
def needs_filter_processing(self) -> bool:
    """只有裁剪、淡变 —— 这些必须逐片段/整片加工，concat demuxer 表达不了。"""
    return bool(self.trim_head or self.trim_tail or self.fade_in or self.fade_out)
```

区别很重要：**压缩虽然也要编码，但不妨碍用 concat demuxer 直连（策略 E）**；
而裁剪/淡变必须逐片段处理。曾经因为把 compress 也算进 `needs_filter_processing`，
导致策略 E 永远选不中（这是个真实 bug，见 [11](./11-踩坑集锦.md)）。

## choose_strategy()：决策逻辑

```python
# merger.py:672（精简）
def choose_strategy(report, options):
    if options.force_strategy:              # 用户强制
        return options.force_strategy
    if options.compress is not None:        # 有压缩档位
        if report.is_uniform and not options.needs_filter_processing:
            return Strategy.ENCODE_CONCAT   # → E
        return Strategy.NORMALIZE_CONCAT    # → B（归一化时套压缩）
    if report.is_uniform and not options.needs_reencode:
        return Strategy.LOSSLESS_CONCAT     # → A
    if options.needs_reencode:
        return Strategy.NORMALIZE_CONCAT    # → B
    dev, maj = report.minimal_reencode_plan()
    if dev and maj:
        return Strategy.MINIMAL_REENCODE    # → D
    return Strategy.NORMALIZE_CONCAT        # → B
```

一句话概括决策树：

```
有压缩？ ── 参数一致且无裁剪淡变 → E
        └─ 否则 → B（归一化时套压缩）
无压缩？ ── 完全一致且无需重编码 → A
        ├─ 需要重编码 → B
        └─ 少数偏离 → D ／ 其余 → B
失败兜底 → C
```

## plan_merge()：把策略变成命令序列

`plan_merge()` 返回 `(strategy, list[PlanStep])`。每个 `PlanStep` 是一条 ffmpeg 命令 + 进度信息。

**策略 A / E**：只有一步，直接用 concat list 拼接（A 加 `-c copy`，E 加一次编码）。

**策略 B（归一化拼接）**分两阶段：

1. 逐片段 `build_normalize_cmd()` —— 统一到目标参数（缩放补边、帧率、像素格式、采样率）；
2. 无损拼接这些归一化片段。

如果还有淡变，则在拼接后再加一步 `build_fade_cmd()`。

**策略 D**：`_build_minimal_steps()` 只归一化偏离片段，多数派原样，最后按原顺序拼接。

**策略 C**：`build_filter_concat_cmd()` 用 concat 滤镜一次性重编码。

## 命令构建的三个精妙之处

### 1. 无损拼接的 `-copyts`

`build_lossless_cmd()` 里加了 `-copyts`，是为了消除 23ms 起始偏移：

```
不加 -copyts：输出起始 0.023s，时长 18.023s（多 23ms）
加 -copyts  ：输出起始 0.000s，时长 18.000s，帧数 432 = 18×24 精确匹配
```

这 23ms 单看不起眼，逐集累积会造成长剧音画漂移。详见 [11](./11-踩坑集锦.md)。

### 2. 淡变场景避免二次压缩

当「压缩 + 淡变」同时出现时：归一化阶段**刻意不压缩**（`use_compress = compress and not fade`），
把压缩留到最终淡变编码那一步一次完成。否则会「归一化压一次 + 淡变压一次」造成二次画质损失。

### 3. 无音轨片段补静音

用 lavfi 生成独立静音输入（`anullsrc`），并**指定时长**——不能用 `anull` 滤镜接视频流，
且不指定时长的无限音源会让 concat 永不结束。

## execute_merge()：执行与自动降级

```python
# merger.py:857（精简）
def execute_merge(...):
    strategy, steps = plan_merge(...)
    try:
        run_steps(strategy, steps)
    except RuntimeError as exc:
        if strategy in (E, D, B) and not force_strategy:
            # 自动降级到策略 C（兼容性最强）
            strategy = Strategy.FILTER_CONCAT
            _, csteps = plan_merge(..., force_strategy=C, ...)
            run_steps(strategy, csteps)
        else:
            raise
    return MergeResult(...)
```

E/D/B 任一失败，只要不是用户强制的，都会自动降级到 C 重试——保证「总能出片」。
所有警告（含降级信息）收进 `MergeResult.warnings` 反馈给用户。

## 进度解析：两个线程避免死锁

`_run_ffmpeg_with_progress()` 用**两个独立线程**分别读 stdout（进度）和 stderr（警告日志）。
这是踩过大坑的：如果串行读，当 ffmpeg 往 stderr 大量输出警告（拼接多集时常见的
`Non-monotonic DTS`）填满管道缓冲区，ffmpeg 会阻塞，主线程又在等 stdout → 死锁假死。
详见 [11](./11-踩坑集锦.md)。

## 小结

- 五档策略按代价从低到高：A → D → E/B → C；
- `needs_filter_processing` vs `needs_reencode` 是选择策略的关键区分；
- `plan_merge` 规划、`execute_merge` 执行 + 自动降级；
- `-copyts`、`lavfi` 静音、避免二次压缩是命令构建的精髓。
