# 04 · 媒体探测与一致性分析

> 对应源码：`drama_merger/probe.py`
> 学习目标：理解「如何判断素材能不能无损拼接」——这是策略选择的依据。

## 核心数据结构

### MediaInfo —— 单集媒体画像

`probe_file()` 调用 ffprobe 得到每集的参数，封装成 `MediaInfo`：

- 视频流：`codec_name`、`width`、`height`、帧率、像素格式、`profile`、`time_base`...
- 音频流：编码、采样率、声道数
- `duration`、`size`、`has_video`、`has_audio`

有一组便捷属性（`width`/`height`/`fps`）方便上层直接用。

**容错**：探测失败的片段会记录 `probe_error`，后续合并时自动跳过，不会让 whole batch 崩掉。

## 一致性分析：判断能不能无损拼接

`analyze_consistency(items)` 产出 `ConsistencyReport`，它回答三个关键问题：

### 问题 1：所有片段参数完全一致吗？

```python
# probe.py:338
@property
def is_uniform(self) -> bool:
    return not self.inconsistencies
```

如果一致 → 走策略 A 无损拼接，秒级完成、画质零损失。

### 问题 2：不一致的话，差异在哪、严不严重？

`check()` 逐字段比对（分辨率、帧率、编码、像素格式、采样率、声道、音轨有无...），
记录成 `Inconsistency`，带 `severity`：

- `blocker`（阻断）：如编码不同、音轨缺失，必须处理才能拼；
- `warning`（提示）：可容忍或建议处理。

`probe` 命令会把这些差异逐条打印出来，并标注「阻断/提示」。

### 问题 3：有没有「少数偏离」的情况？

这是本工具一个很聪明的判断。真实短剧里常见：36 集里 35 集是 1080p，只有 1 集是 4K/HEVC。
如果把 36 集全部重编码就太亏了。`minimal_reencode_plan()` 找出：

- **多数派组**（majority）：参数一致的那些；
- **偏离片段**（deviating）：少数几个「异类」。

据此可走策略 D：只重编码那 1 集，其余 35 集原样复制（零损失），比全部重编码快一个数量级。

### 目标参数与「多数派 profile/timescale」

报告还提供：

- `target_video_params()` / `target_audio_params()` —— 归一化目标（取多数派分辨率 + 最高帧率等）；
- `target_profile()` / `target_timescale()` —— 多数派的 H.264 profile 和视频时间刻度。

后两者很关键：走策略 D 时，重编码的那几个片段必须**对齐多数派的 profile 和 timescale**，
否则 `-c copy` 拼接会失败或产生异常时间戳（见 [05](./05-合并策略引擎-merger.md) 与 [11](./11-踩坑集锦.md)）。

## 探测的降级路径

`probe_file()` 优先用 ffprobe（JSON 输出，最准）；没有 ffprobe 时用
`_probe_via_ffmpeg()` 解析 ffmpeg 的输出兜底。打包版如果没带上 ffprobe 也能工作。

## 小结

- `collect_video_files()`：自然排序，顺序正确是前提；
- `MediaInfo`：每集画像，带容错；
- `ConsistencyReport`：三个问题（是否一致 / 差异严重性 / 少数偏离）直接决定策略。
