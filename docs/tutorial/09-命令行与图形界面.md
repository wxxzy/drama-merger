# 09 · 命令行与图形界面（双入口）

> 对应源码：`cli.py`、`gui.py`、`cli_entry.py`、`gui_entry.py`
> 学习目标：理解如何在一套核心库上套两种壳，以及 GUI 的线程模型。

## 命令行：cli.py

`cli.py` 用 argparse 组织六个子命令：

| 子命令 | 作用 |
|---|---|
| `probe` | 探测目录、分析一致性（只读） |
| `merge` | 合并（支持压缩/裁剪/淡变/字幕） |
| `presets` | 列出压缩档位 |
| `publish` | 生成发布素材 |
| `gui` | 启动图形界面 |
| `--version` | 版本信息 |

每个子命令对应一个 `cmd_xxx(args)` 函数，`main()` 通过 `args.func(args)` 分派。

### ConsoleProgress：两种进度显示模式

```python
# cli.py:76
class ConsoleProgress:
    def __init__(self, stream=None):
        self.is_tty = bool(getattr(self.stream, "isatty", lambda: False)())
```

- **TTY（真实终端）**：用 `\r` 原地重绘进度条，且仅在百分比变化时刷新；
- **非 TTY（输出被重定向/工具捕获）**：`\r` 不生效，改为每跨 10% 打印一行，日志保持可读。

这个区分很实用——既照顾交互式用户，也让自动化日志不变成一长串乱码。

## 图形界面：gui.py

`MergeApp` 是主窗口类。布局用 `ttk.Notebook` 分成两个标签页：

```
① 合并视频  ── 选目录 → 扫描 → 选项 → ▶ 开始合并
② 发布准备  ── 选成片 → 剧名/封面 → ▶ 生成发布素材
底部共用：进度条 + 状态栏 + 运行日志
```

**为什么用标签页**：合并与发布是两个前后相继但操作独立的环节，同一屏堆叠控件会让窗口过高、
关键按钮被挤出视野（踩过这个坑）。标签页让各自内部空间充裕（详见 [11](./11-踩坑集锦.md)）。

### 线程模型：不卡界面

GUI 最忌讳在主线程做耗时操作。工具的做法：

```python
# gui.py（概念）
def on_merge(self):
    def work():                    # 后台线程
        result = execute_merge(...)
        self._log(...)             # 通过队列回传
        self._ui(lambda: messagebox.showinfo("完成", ...))
    threading.Thread(target=work, daemon=True).start()

def _poll_queue(self):             # 主线程定时轮询
    while True:
        fn = self.msg_queue.get_nowait()
        fn()                       # 所有 UI 更新都在主线程执行
    self.root.after(80, self._poll_queue)
```

关键点：**所有 UI 操作通过 `msg_queue` 排回主线程**（`_ui()` 把函数入队，`_poll_queue()` 定时取出执行），
因为 tkinter 不是线程安全的。ffmpeg 探测、合并、发布全在后台线程跑，界面始终响应。

进度回调 `on_progress` 也是这个思路：后台算出进度 → `_ui` 入队 → 主线程更新进度条。

## 两个 Entry 模块：打包专用

`cli_entry.py` 和 `gui_entry.py` 是 PyInstaller 打包的入口，比直接跑 cli/gui 多了两件事：

### 1. 注入捆绑 ffmpeg 路径

```python
def _bootstrap_ffmpeg():
    base = Path(getattr(sys, "_MEIPASS", ...))
    for cand in (base/"ffmpeg/ffmpeg.exe", ...):
        if cand.is_file():
            os.environ.setdefault("DRAMA_MERGER_FFMPEG", str(cand))
            return
    # 按模式兜底（PyInstaller 可能保留带版本号的文件名）
```

打包后资源在 `sys._MEIPASS` 临时目录，把里面的 ffmpeg 路径注入环境变量，
探测模块就能优先用它（见 [03](./03-环境探测.md)）。

### 2. 兜底标准输出流

`gui_entry.py` 里有个 `_NullWriter`：

```python
class _NullWriter:
    def write(self, *_args): return 0
    def flush(self): return None
```

原因：GUI 用 `console=False`（windowed）打包后，`sys.stdout` 是 `None`。
底层若有 `print` 会直接崩溃。用空写入器兜底就安全了（真实坑，见 [11](./11-踩坑集锦.md)）。

### 3. 不 chdir

两个入口都刻意**不改变工作目录**——否则用户给的相对路径（`-o out.mp4`）会被解析到 exe 目录，
结果文件「凭空消失」在某个意想不到的地方，很难排查。

## 小结

- 六个 CLI 子命令，对应六个 `cmd_xxx`；进度条区分 TTY/非 TTY；
- GUI 用标签页分区，耗时操作放后台线程，UI 更新经队列回主线程；
- 两个 entry 处理打包特有问题：注入 ffmpeg、兜底 stdout、不 chdir。
