# 02 · 整体架构：模块分层与数据流

> 学习目标：建立全局心智模型，知道每个文件在做什么、数据怎么流动。

## 分层视图

项目可以清晰地分成四层：

```
┌─────────────────────────────────────────────────────┐
│  入口层（Entry）                                     │
│  cli.py / gui.py / cli_entry.py / gui_entry.py       │
│  职责：参数解析、界面交互、进度展示                    │
└───────────────────┬─────────────────────────────────┘
                    │ 调用
┌───────────────────▼─────────────────────────────────┐
│  编排层（Orchestration）                             │
│  merger.py  ·  publish.py                           │
│  职责：策略决策、命令规划、执行调度、发布素材编排       │
└───────┬───────────────────────────┬─────────────────┘
        │ 调用                      │ 调用
┌───────▼──────────────┐  ┌─────────▼─────────────────┐
│  能力层（Capability） │  │  数据层（Data）           │
│  compress.py         │  │  probe.py                 │
│  subtitles.py        │  │  ffmpeg_env.py            │
│  职责：编码参数、字幕  │  │  职责：环境发现、媒体探测   │
│  处理、缩略图          │  │  、一致性分析             │
└──────────────────────┘  └───────────────────────────┘
```

## 核心模块一览表

| 文件 | 层 | 核心职责 | 关键数据结构/函数 |
|---|---|---|---|
| `ffmpeg_env.py` | 数据 | 找到可用的 ffmpeg，实测 NVENC | `FfmpegEnv`, `get_ffmpeg_env()` |
| `probe.py` | 数据 | 探测媒体参数、自然排序、一致性分析 | `MediaInfo`, `ConsistencyReport`, `analyze_consistency()` |
| `merger.py` | 编排 | 策略决策、命令构建、执行（**大脑**） | `Strategy`, `MergeOptions`, `plan_merge()`, `execute_merge()` |
| `compress.py` | 能力 | 压缩档位定义 | `CompressPreset`, `PRESETS`, `get_preset()` |
| `subtitles.py` | 能力 | 字幕解析、时间轴平移、烧入 | `Cue`, `EpisodeSubtitle`, `merge_subtitles()` |
| `publish.py` | 编排 | 章节/文案/缩略图、剧目模板 | `DramaMeta`, `generate_all()`, `DRAMA_TEMPLATES` |
| `cli.py` | 入口 | 命令行子命令 | `cmd_probe/cmd_merge/cmd_publish/...` |
| `gui.py` | 入口 | Tkinter 界面、后台线程 | `MergeApp` |
| `build.spec` | 构建 | PyInstaller 打包配置 | 两个 EXE + 一个 `_internal` |

## 主合并链路的数据流

以 `cli.py merge` 为例，一次合并的数据流：

```
目录路径
   │ collect_video_files()        ← probe.py，自然排序
   ▼
list[Path] 视频文件列表
   │ probe_file() × N             ← probe.py，逐个 ffprobe
   ▼
list[MediaInfo]                   ← 每集的参数画像
   │ analyze_consistency()        ← probe.py，比对签名
   ▼
ConsistencyReport                 ← 是否 uniform？差异在哪？多数派是谁？
   │ + MergeOptions（用户选项）    ← 编码器/压缩/裁剪/淡变
   ▼
choose_strategy()                 ← merger.py，决定 A/D/B/C/E
   ▼
plan_merge() → list[PlanStep]     ← 每一步是一条 ffmpeg 命令
   │ execute_merge()              ← 逐步执行，解析进度，失败自动降级
   ▼
MergeResult                       ← 输出路径、策略、耗时、大小、日志
```

关键设计：**「决策」与「执行」分离**。
`plan_merge()` 只生成命令列表，不执行——所以 `--dry-run` 能原样打印将要执行的命令，
GUI 能在合并前展示「将采用什么策略、分几步」。`execute_merge()` 才真正跑 ffmpeg。

## 压缩与发布两条支线

```
压缩支线：compress.py 的 CompressPreset 被注入 MergeOptions.compress
          → merger.py 构建命令时套用档位参数（见 07）

发布支线：视频目录 + 剧名 → publish.match_template() 取文案模板
          → generate_all() 产出：章节时间轴 + 发布文案 + 缩略图（见 08）
```

## 设计亮点速览

1. **库与壳分离**：业务逻辑全在 `drama_merger/` 包里，CLI/GUI 只是两层薄壳。
   因此新增一个入口（比如 Web API）几乎不用改核心代码。
2. **模板数据下沉**：剧目文案放在 `publish.py`（库），不放 `gui.py`——
   否则命令行版会被迫依赖 tkinter（这是个真实踩过的坑，见 [11](./11-踩坑集锦.md)）。
3. **运行时能力探测**：不硬编码「能不能用 NVENC」，而是启动时真跑一次编码测试
   （`ffmpeg_env.py::_verify_nvenc`），适应不同机器/驱动/ffmpeg 版本。
4. **双 exe 共享运行时**：打包时 GUI 与 CLI 共享一份 `_internal`，ffmpeg 只存一份（见 [10](./10-打包成免安装程序.md)）。

## 小结

- 四层：入口 → 编排 → 能力/数据；
- 主链路：探测 → 分析 → 决策 → 规划 → 执行；
- 记住 `plan_merge` / `execute_merge` 的分离，它是理解一切的关键。
