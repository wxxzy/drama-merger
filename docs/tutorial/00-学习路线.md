# 00 · 学习路线：如何阅读这套教程

> 这套教程面向「想真正读懂 drama-merger 实现」的人。它不是 README 的复制品，
> 而是沿着代码本身的脉络，把「为什么这么设计」讲清楚。

## 这个工具解决什么问题

把「指定目录下的多集短剧」合并成「一部完整视频」，听起来是个简单需求，但真正做起来
会踩一堆坑：

- 每集参数（分辨率/帧率/音轨）不一致，直接拼会失败；
- 分集字幕各自从 `00:00:00` 开始，拼完字幕全部错位；
- 无损拼接有 23 毫秒时间戳偏移，逐集累积会造成音画漂移；
- 合并出来的文件太大，还得二次压缩；
- 发布到 YouTube 还要手工整理章节、文案、缩略图……

drama-merger 把这些痛点系统性解决掉了，并且做到了「能用就绝不重编码」。

## 三条阅读路径

**路径 A：我只想用它**（读 01 即可）
> 快速上手 → 会点按钮、会敲命令就够了。

**路径 B：我想理解设计**（读 00→02，再挑感兴趣的模块）
> 整体架构是枢纽，后面各篇都依赖它建立的心智模型。

**路径 C：我要二次开发 / 排错**（通读 00~12）
> 尤其是 05（策略引擎）、11（踩坑集锦）、12（测试与扩展）。

## 阅读约定

- 文中出现的 `drama_merger/xxx.py:123` 表示源码文件与行号，可对照阅读；
- 关键代码片段会单独列出，并标注它解决什么问题；
- 每篇末尾有「小结」和「思考题」，用来检验理解程度。

## 一句话心智模型

> **探测（probe）→ 决策（choose_strategy）→ 规划（plan_merge）→ 执行（execute_merge）**
>
> 整个工具就是这条链，其余模块要么给它提供能力（ffmpeg/compress/subtitles），
> 要么给它套一层壳（cli/gui/publish）。

准备好就从 [01-快速上手](./01-快速上手.md) 开始吧。
